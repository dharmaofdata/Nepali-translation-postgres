# Где Developer Guide оказался неточным

Статус по ревью @yoda (2026-09-11). Решения внесены в Developer Guide.

1. **§25, descriptors.** ACCEPT: `artifact_delivery_path` и `peers_see_silence` в
   `laptop-nsnode.provides` (последнее после теста нода → нода); `processes_gone`
   в `planned_provides` pi5 и laptop-vm; `isolated_network_identity` для pi5.
   Явного решения не было по остальным добавлениям в `planned_provides`:
   pi5 — `disk_preserved`, `artifact_delivery_path`; laptop-vm —
   `isolated_network_identity`, `disk_preserved`, `artifact_delivery_path`.
2. **§28, relaxations без `breaks`.** Открыто. В каталоге только три relaxations с
   определёнными `breaks`. Для Class B нужен словарь «путей» (`reset_path`,
   `inventory_discovery`, `results_channel`, …).
3. **§29, ноль mandatory checks.** ACCEPT: запрещено при validation; `verdict()`
   защитно возвращает INCONCLUSIVE.
4. **Ошибка исполнения.** ACCEPT: `run_status=error`, `verdict=null`; отказ по stub или
   preflight — не run, record не пишется.
5. **§38, backend в сценарии.** ACCEPT: backend — параметр запуска; в сценарии только
   `fidelity.<backend>`.
6. **Fault actions backend'а.** ACCEPT: `actions` / `planned_actions`.
7. **`faults.at`.** ACCEPT: от `workload_started`.
8. **Неоднозначный selector.** ACCEPT: ровно одна доступная нода, иначе ошибка.
9. **§26, наблюдение bench.** ACCEPT с изменением: вместо `node_processes()` —
   `observe(node, semantic)` с backend-specific evidence (сделано, 30e0227).
10. **Controller на laptop.** Принято как упрощение skeleton; controller-as-role
    остаётся в «не доказано».

## Найдено на слайсе с настоящим PostgreSQL

11. **Service lifecycle шире, чем start/stop/status/role (§6).** Настоящему сервису
    нужен отдельный `deploy` (initdb или pg_basebackup) и порядок ролей: standby
    строится от работающего primary. В guide этого шага нет.
12. **Checks нуждаются не только в наблюдении bench (§26), но и в наблюдении
    сервиса.** Добавлен `probe` у адаптера; его содержимое непрозрачно для core.
13. **Node-local config — это не только intent (§13.1).** Часть effective config
    может быть задана только на ноде: socket dir, primary_conninfo. Рендерит агент.
14. **Артефакт как дерево, а не файл.** Нужны `entrypoint` и распаковка в кэш ноды.
15. **Backend без mount/ipc namespace оставляет состояние после node.off.**
    Осиротевшие `/dev/shm/PostgreSQL.*` и SysV-сегменты. Это аргумент к следующему
    шагу изоляции nsnode, и его стоит назвать в §31.1 явно.

## Найдено на слое жизненного цикла ноды

16. **Fault'ы перестали быть односторонними, и это меняет модель проверок (§29).**
    Check должен опираться на наблюдения, снятые вокруг fault'а, а не на состояние
    в момент оценки: к этому времени перезапущенная нода снова жива.
17. **У action есть состояние цели.** `node.on` целится в недоступную ноду, поэтому
    selector не должен отфильтровывать её как unavailable. Добавлен `target_state`.
18. **Selector по предыдущему fault'у.** Чтобы сценарий не называл ноду по имени
    при `node.on`, нужен `{node_of: N}` — «та нода, которую выключил fault N».
19. **`disk_preserved` — семантика хранилища, а не namespace'ов** (поправка @yoda,
    подтверждена реализацией: namespace'ы умирают с нодой, диск живёт на хосте).
20. **Инвариант «результат не зависит от того, был ли артефакт закеширован» (§36)
    проверяется только при перезапуске.** Вернувшийся агент имеет кэш на диске и
    не помнит артефакта, поэтому `fetch` выполняется при каждом подъёме сервиса.
21. **`observes` в дескрипторе check'а должен быть обязывающим, а не описательным.**
    Guide не говорит, что видит check. Пока он видел объединение наблюдений всех
    check'ов сценария, проверка могла читать незадекларированную семантику — и на
    backend'е, который её не даёт, молча теряла защиту от вакуума, оставаясь PASS.
    Исполнитель теперь отдаёт каждому check'у отфильтрованный вид.
22. **Ожидаемое множество узлов выводится из inventory и списка fault'ов, а не из
    ответов сервиса.** Иначе нода, до которой не дозвонились, исчезает из обеих
    частей сравнения. Для HA это тот же вопрос: «старый primary не стал writable»
    не должно означать «мы до него не дозвонились».

## Найдено на примитиве process.pause

23. **Доступность ноды — наблюдение, а не событие потери.** Guide описывает только
    обнаружение отказа. Нода, чьи процессы остановили и пустили снова, начинает
    отвечать по тому же соединению, без повторной регистрации, и контроллер обязан
    это увидеть.
24. **У примитива возвращения два разных смысла.** После перезагрузки сервис
    потерян и его надо поднимать; после resume и агент, и сервис те же. Примитив
    сообщает об этом сам (`service_lost`), иначе исполнитель передеплоит сервис и
    уничтожит проверяемое состояние.
25. **Пауза не видна клиенту как ошибка.** Ядро замороженной ноды подтверждает
    пакеты, поэтому клиентские таймауты не срабатывают. Для сценариев про lease
    это ключевое свойство, и его стоит назвать в §16 рядом с `node.off`.

## Найдено на первом HA-слайсе

26. **Роль, членство и нода — три разные вещи (§9).** Для HA-сервиса исполнитель
    восстанавливает членство и наблюдает роль; `initial.primary` — только старт.
27. **`nodes.count` — число логических нод эксперимента**, а не нод с базой.
    Координатор (монитор, DCS) — сервис со своим placement, и специального понятия
    для него в ядре нет.
28. **Артефакт может обслуживать несколько типов сервиса.** Поставка, где лежат и
    PostgreSQL, и управляющий им инструмент, — один артефакт.
29. **Пробы нужны вокруг каждого fault'а**, иначе сценарий, в котором роль меняется
    в середине, нечем описать. Окно недоступности при этом всё равно не покрыто:
    нужна проба по расписанию, а не только по событиям.
30. **Проверка должна опираться на placement, а не на то, кто ответил** — иначе
    «старый primary не стал writable» вырождается в «мы до него не дозвонились».
